## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** `is_legal` is a direct transcription of the ratified PAEOS-7 §4.1 edge table
(PAEOS-IP-0003). Deny-by-default (FR-4) is the return contract. CER-5/CER-6 honoured: the
weight-class contradiction and the failure-edge scope were **not** resolved by the runtime —
they were escalated (IP-0003) and only implemented after founder ratification.

### 2. Architectural Drift
**PASS.** No concept beyond the ratified table. The edge set is *derived from the ratified
ordered chain* (`itertools.pairwise(_MAIN_CHAIN)` + the one cycle edge) rather than hand-listed,
so it cannot drift from the spec silently. The only two extra edges are the ratified ROUTINE
compression edges, isolated in a named `ROUTINE_FASTPATH_EDGES` set.

### 3. Duplication of Mechanisms
**PASS.** Reuses `StageId`/`WeightClass` from `kernel/types.py` (B0.4). No re-declaration of
stages or classes. The test keeps an *independent* copy of the chain — intentional duplication
(a spec oracle), not code duplication.

### 4. Bypassing Mechanisms
**PASS.** Nothing bypassed. `is_legal` is a pure function over frozen sets; no I/O, no state.

### 5. Simpler Implementation Possible
**PASS / minimal.** Two frozensets + a 3-line predicate. No graph library, no per-stage config.
Building the forward set from the chain is the smallest correct encoding.

### 6. Better Derivation
**PASS.** The derivation *is* the ratified table; there is no cleaner form. Deriving the edge
set from the chain (rather than typing 21 tuples) removes a transcription-error class.

### 7. Hidden Technical Debt
**PASS.** None hidden. The one deferral (failure/remand edges) is a *ratified design decision*
(IP-0003 Part A: kernel-routed, not `is_legal`), not debt. No `DEBT-NNNN` warranted.

### 8. Security Implications
**PASS (with the right posture).** As a reference-monitor oracle, the safe failure mode is
*deny*. `is_legal` returns `False` for everything not explicitly legal — a false-negative
(deny-legal) is safe (FR-4), a false-positive (allow-illegal) is not, and none exist: the
1323-combination test pins every pair. The ROUTINE compression edges cannot be reached by a
`KERNEL_TOUCHING` goal (weight class is set at TRIAGE before the edge is offered; tested).

### 9. Runtime Implications
**PASS.** O(1) frozenset lookups; no blocking, allocation, or error paths.

### 10. Future Extensibility
**PASS.** B0.6 (gates) consumes `is_legal` as step 2 of the four-tuple check; the pure-function
shape composes cleanly. If future weight-class edges are ratified, they extend
`ROUTINE_FASTPATH_EDGES` (or a new set) without touching the forward chain.

chamber-level and are `Outcome`s per §4.4; (B) the corpus **contradicted itself** on weight-class
edges (PAEOS-9 §2.3 "shape invariant" vs `WORKFLOW_STATE_MACHINE.yaml` `L02→L12` vs the B0.5
acceptance "edges differ"). Per the preamble the runtime **halted before writing code** and filed
PAEOS-IP-0003. Founder **RATIFIED** both parts; implementation is a faithful transcription of the
ratified table. Spec amended (PAEOS-7 §4.1 canonical edge table).

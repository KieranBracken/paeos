## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** Implements §5.3: canaries are known-bad artifacts a detector must catch; a miss is the
FR-2/FR-3 tripwire. The format is documented (Z0), one seed exists, and the harness records
catch/miss — exactly the B0.14 acceptance ("harness can submit a canary and record catch/miss;
real catching arrives with the court in Phase 1").

### 2. Architectural Drift
**PASS.** No new mechanism. The harness is detector-*agnostic* — the detector is injected, so no
Court logic is invented here (that is Phase 1). The seed reuses an existing defect class the kernel
already catches (forged evidence / T2), rather than inventing a new one.

### 3. Duplication of Mechanisms
**PASS.** The seed canary's detector (in the test) reuses `kernel.evidence.verify_deterministic` —
the real T2 defense — as the Phase-0 stand-in for the Court. No re-implementation.

### 4. Bypassing Mechanisms
**PASS.** Nothing bypassed. `load_canary` validates the JSON shape (object + object artifact + string
fields) and raises on malformed canaries.

### 5. Simpler Implementation Possible
**PASS / minimal.** Two frozen records + a loader + a submit function. JSON, no schema library.

### 6. Better Derivation
**PASS.** `passed = caught == (expected is CAUGHT)` is the direct expression of "a correct detector
catches a CAUGHT-expected canary"; a miss is a first-class recorded result, not an exception.

### 7. Hidden Technical Debt
**PASS.** None. Growing the canary corpus and running calibration through the real Court is Phase-1
work (Observation 1), not deferred debt.

### 8. Security Implications
**PASS.** Canaries are the calibration of the safety tripwire itself. The seed proves the loop end
to end: a correct detector catches CANARY-0001; a **blind** detector produces a recorded MISS
(`passed=False`) — so a miscalibrated detector is *visible*, which is the whole point. The seed's
`detection_signature` names the exact mechanism to fix on a miss.

### 9. Runtime Implications
**PASS.** Pure loading + a detector call; the test detector runs one subprocess (echo) via the
evidence module's bounded reproduction. No leaks.

### 10. Future Extensibility
**PASS.** New canary categories (illegal-transition, stale-replay, power-fusion, …) are new
`CANARY-NNNN.json` files; the harness is unchanged. In Phase 1 the injected detector becomes the
Court running the artifact end-to-end (Observation 1).

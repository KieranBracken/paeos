## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** Roles are **capability profiles, not personalities** (7 §5): each stage's scoped
`TaskPackage` is derived from a `RoleSpec` (objective, write/read scopes, MCP allow-list, required
evidence, skills). The §5.2 catalog is honoured — the Planner **cannot write production code** (scope
`design/`/`plan/`, enforced by the dispatcher's `write_scopes`), and the Builder holds no seal/merge/
ledger authority (its MCP allow-list excludes them; append is unreachable via B1.A anyway).

### 2. Architectural Drift
**PASS.** No new mechanism — `StagePlaybook` is a thin lookup + dispatch over B1.B. Skills are `SkillRef`
declarations (§9); the registry that resolves them is a later task (Observation 2).

### 3. Duplication of Mechanisms
**PASS.** Reuses the dispatcher, capability, evidence-obligation, and package contracts.

### 4. Bypassing Mechanisms
**PASS.** IMPLEMENT **requires** plan-supplied `write_scopes` (a Builder with no scope cannot run) —
the plan, not the builder, decides what it may touch. A Planner writing outside `design/`/`plan/` is
refused by the dispatcher.

### 5–7. Simplicity / Derivation / Debt
**PASS.** Frozen specs + a dict + a dispatch wrapper; the required-evidence obligations map to the
court's claims (B1.E). No hidden debt.

### 8. Security Implications
**PASS.** Each role's authority is exactly its `RoleSpec` — least authority per stage. The
separation of powers (SI-3) is enforced at the gate (B0.6); these specs set the scoped grants the
gate later checks.

### 9–10. Runtime / Extensibility
**PASS.** Pure construction; new stages/roles are new `RoleSpec` entries; the soft loop (integration)
calls `run_stage` per stage.

# DEBT-0059 — Transaction Claims Lack Cross-Process Compare-and-Swap

Status: **OPEN** · Filed: 2026-08-25 · Channel: CER-3
Priority: **blocking-before-multiple-overseer-adapters-or-live-canary**
Source: Founder-requested Codex-to-Antigravity quota handoff analysis after control-plane recovery
Subproject 1.

## 1. Compromise

`TransactionStore.save()` proves that one appended transition exactly replays through the pure
reducer, then writes the replacement record atomically. It does not lock the transaction or prove
that the bytes loaded before reduction are still the current bytes at replacement time.

Two independent adapter processes can therefore load the same `PREPARED` record, independently
produce valid `CLAIM` transitions with different lease owners, and race through `os.replace()`.
The final writer wins even though both callers observed success. Atomic replacement prevents a
torn file; it does not provide compare-and-swap semantics.

## 2. Reason

Subproject 1 implemented the approved single-consumer protocol foundation and deliberately did
not activate an overseer adapter. Cross-process claim arbitration only became an executable
requirement when the Founder required quota-driven handoff between Codex and Antigravity.

## 3. Ideal Solution

- Serialize each transaction update with a state-root-local, cross-process lock.
- While holding the lock, reload the current canonical bytes and verify the expected prior digest.
- Apply exactly one reducer transition and durably replace the record.
- Return the committed record and digest; never report a claim from pre-commit worker text.
- Treat stale lock recovery and uncertain commits as `RECONCILIATION_REQUIRED`, never as an
  automatic retry or lease transfer.
- Prove with real competing processes that exactly one claimant commits and the loser fails closed.

## 4. Repayment Conditions

Debt is repaid only when a discriminative multiprocess test starts two claimants against one
`PREPARED` transaction and proves exactly one durable `CLAIM`, one losing conflict result, no
overwritten lease owner, no duplicate response, and no automatic replay. The same test must fail
when the lock/CAS guard is removed.

## 5. Estimated Impact

Without repayment, simultaneous or overlapping Codex and Antigravity consumers can both believe
they own the same request. That can duplicate oversight responses, overwrite provenance, and make
quota failover less safe than a manual handoff.

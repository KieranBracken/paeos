# DEBT-0002 — B0.0 Day-1 spawnability spike not yet executed

Status: **ACCEPTED (tracked, non-blocking)** · Filed: 2026-07-22 · Channel: CER-3 · Priority: **HIGH (load-bearing)**

## Founder acceptance (2026-07-27)

> "A debt is not the same thing as a blocker. **DEBT-0002 is accepted as constitutional
> debt rather than a blocking defect.** It remains scheduled according to the implementation
> roadmap. It does not block B0.1." — Founder (Kieran Bracken)

Ratified per CER-5 (separation of powers): the runtime *recorded* the compromise; the
founder *legislates* its disposition. This item is **non-blocking for B0.1** and stays
**gating for Phase-1 planning** (repayment condition below is unchanged — the spike MUST
be green before Phase 1 is planned). Acceptance changes the status from an open defect to
tracked, scheduled debt; it does **not** waive the repayment condition.

## Compromise

B0.0 (PAEOS-8 §10) includes a **Day-1 spike**: prove that Claude Code sessions can be spawned
**programmatically** with a scoped workspace + an MCP allow-list in the target environment
(PAEOS-8 §13.2 assumption 1; PAEOS-9 execution-architecture §…"single most important external
dependency"). The build deliverables of B0.0 (repo skeleton, toolchain, docker-compose, CI +
live TCB gates) are complete and evidence-backed; **the spawnability spike was NOT executed.**

## Reason

The spike cannot be run from inside a single Claude Code session against itself — it requires
driving the actual agent-runtime environment (programmatic session spawning + MCP scoping),
which is a founder/ops action in the target environment, not something this build session can
self-validate.

## Ideal solution

A standalone spike script/harness that: spawns a Claude Code session programmatically, hands it
an isolated workspace limited to declared `write_scopes`, restricts it to an MCP allow-list,
and confirms it cannot read/write outside scope. Record catch/result. This proves FR-3
(information barriers) and SI-5 are achievable before Phase 1 is planned.

## Repayment conditions

**Before Phase 1 is planned** (PAEOS-8 §13.2 is explicit: "must prove it before Phase 1"). If
the spike FAILS, the agent-runtime decision reopens (PAEOS-7 §13) — so this is a gating risk,
not a routine deferral.

## Priority

HIGH. It is the single most important external dependency of the whole autonomous runtime. B0.1
(the ledger) does not depend on it and may proceed; but Phase 1 MUST NOT be planned until this
is green.

## Estimated impact

If unvalidated and later false: the entire agent-orchestration architecture (runtime/ Z2,
agent_dispatcher, information barriers) needs rework. If validated: no impact. High variance —
which is exactly why it is Day-1 and why leaving it open is tracked here rather than assumed.

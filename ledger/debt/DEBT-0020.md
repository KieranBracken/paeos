# DEBT-0020: T2 Evidence Result Normalization Lacks Formal Specification

## 1. Context
During Phase 3 Milestone 3 (CER-1), `_normalized_result()` was added to `kernel/evidence.py` to strip trailing whitespace (`stdout.rstrip()`) during deterministic verification (`verify_deterministic`).

## 2. Problem & Risk
While practically necessary to prevent false-negative remands when live agents print `"PASS"` while subshell execution emits `"PASS\n"`, modifying the kernel T2 evidence reproduction gate without an explicit Improvement Proposal (IP) introduces formal specification drift against `PAEOS-4-kernel.md`.

## 3. Recommended Resolution
Formalize the evidence normalization contract via **IP-0011 (T2 Evidence Normalization Protocol)**, defining exact boundary conditions (e.g. trailing whitespace vs. interior/leading whitespace) to ensure anti-forgery bounds remain mathematically proven.

## 4. Status
**PROPOSAL DRAFTED** (2026-08-04) — `proposals/PAEOS-IP-0011-t2-normalization.md` formalizes the
T2 result-equivalence contract (exit_code exact; stdout equal modulo *trailing* whitespace only;
leading/interior/content differences still remand) with an explicit anti-forgery proof. Closes on
founder ratification of IP-0011 (kernel-surface, §14.5 / F2). The implementing code
(`kernel/evidence.py::_normalized_result`) and its tests already exist (M3); ratification supplies
the missing specification.

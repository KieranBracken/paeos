# DEBT-0057 — Tracked Runtime State in the Repository Baseline

Status: **IMPLEMENTATION_REPAID_OPERATOR_ACTION_OPEN** · Filed: 2026-08-25 · Channel: CER-3
Priority: **operator-action-before-credentialed-unattended-use**
Source: `SAKG_AD_011` control-plane recovery Subproject 1, L17 review.

## 1. Compromise

The pinned recovery baseline tracked 622 paths beneath `.paeos_state`, including bridge current
prompt/output files, Court/CAS records, SQLite state, and `seal.key`. It also gave the sidecar
scorer a hidden repository-relative persistence default. The approved recovery froze those bytes
outside the repository, created a new external trust domain, made scorer persistence explicit,
and removed the runtime tree from Git tracking without deleting the historical worktree files.

## 2. Reason

The original recovery contract pinned an immutable baseline and forbade deleting runtime
evidence. The Founder subsequently approved a separate create-only migration plan so the tracked
state could be repaid without destroying provenance or promoting to main/trunk.

## 3. Ideal Solution

- Inventory and hash every tracked runtime artifact.
- Classify evidence that must be retained versus generated/test residue.
- Move retained evidence to an explicit state/evidence store outside source control.
- Rotate `seal.key` and any credential-bearing configuration that may have been exposed.
- Remove runtime state from Git, add a tested ignore policy, and make every runtime/test state root
  explicit and injectable.

## 4. Repayment Conditions

Implementation repayment requires a Founder-approved migration to prove:

- `git ls-files .paeos_state` has no runtime-state entries;
- a clean checkout starts with no bridge/runtime state;
- tests write bridge state only under fixture-owned roots and clean it;
- production-state before/after manifests remain byte-identical during the full suite; and
- the historical signing domain is separated from a newly generated external trust domain.

Those implementation conditions are satisfied. Closure still requires the operator action named
in Section 6.

## 5. Estimated Impact

Leaving the debt open risks state confusion between source and runtime, accidental key exposure,
false isolation proofs, non-hermetic tests, and unsafe promotion of stale bridge transactions.

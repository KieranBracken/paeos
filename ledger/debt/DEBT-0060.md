## 6. Root-cause reconciliation — 2026-08-30

The timeout is reproducible from the current component boundary. `ChatBridgeRuntime` writes an
immutable request to `<state_root>/bridge/requests/<exchange>.prompt.md` and waits for the matching
`<state_root>/bridge/responses/<exchange>.response.md`. The legacy GUI scripts instead watch
`ops/chatgpt_bridge/cline_output.log`, save `ops/chatgpt_bridge/chatgpt_response.md`, and paste to
the front terminal; they never create the correlated response file. A normal run can therefore
wait until the compatibility timeout and emit `BRIDGE_RESPONSE_TIMEOUT` while the GUI process is
alive. Its 20-second poll, 45-second idle gate, and 180-second browser wait explain multi-minute
hesitation; broad exception sleeps obscure the boundary failure.

No legacy GUI mutation was reintroduced. The approved event-watchdog plan remains the safe
remediation path: replace repository/GUI-idle signals with verified transaction events and typed
deadlines, then route recovery through the canonical coordinator. DEBT-0060 remains **OPEN** until
that path is implemented and independently verified; no timeout is relabeled as success.

# DEBT-0003 — Postgres `LedgerStore` backend deferred behind the narrow waist

Status: **PROPOSED (awaiting Founder ratification)** · Filed: 2026-07-27 · Channel: CER-3 · Priority: **MEDIUM**

## Compromise

PAEOS-8 §3/§134 lock **PostgreSQL 16** as the ledger's production persistence ("ACID
single-writer append is exactly FR-5"). B0.1 delivers the full ledger *algebra* (append-
only, hash-chain, single-writer, fork rejection, `verify_chain`) behind the `LedgerStore`
Protocol, proven against `InMemoryLedgerStore`. **The Postgres backend is not yet built.**

## Reason

No docker daemon is available in the build environment, so a Postgres backend cannot be run
or iterated locally — only blind against a CI service. Building the TCB's foundational
module blind against an un-runnable backend is a worse risk than deferring it behind the
`LedgerStore` waist (K9). The algebra it will store is exactly the algebra proven in B0.1;
the Protocol guarantees a drop-in with no change to callers.

## Ideal solution

`PostgresLedgerStore(LedgerStore)`: a `ledger_rows(seq PK, prev_hash, row_hash, ts, event
jsonb, schema_ver)` table with `UNIQUE(seq)` and no UPDATE/DELETE grant to the runtime
role; single-writer via `pg_advisory_lock`; `append_row` in a serialisable transaction so a
racing fork violates `UNIQUE(seq)` and aborts. Plus a CI `services: postgres` block running
the *same* B0.1 test suite against it, and a **cross-restart** durability test (append →
drop connection → reopen → `verify_chain` + identical head).

## Repayment conditions

**By B0.10** (projections + replay): its acceptance requires "replay of the 1k-event corpus
reproduces byte-identical state + head" across a process boundary, which forces a durable
backend. B0.2–B0.9 are storage-agnostic against the Protocol and do **not** require this.

## Priority

MEDIUM. Non-blocking for the next several tasks; becomes blocking at B0.10. Lower variance
than DEBT-0002 — the interface is already isolated, so repayment is additive, not a redesign.

## Estimated impact

If the Postgres backend later reveals a semantic the in-memory backend hid (e.g. true
concurrent-writer races, jsonb canonicalisation differences), the fix is contained to the
backend class — the algebra and its tests are unchanged. Low blast radius by construction.

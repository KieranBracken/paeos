# DEBT-0099 — Confused Deputy Authority Leak: `infer_write_scopes` Confuses Test/Citation Paths with Authorized Write Scopes

Status: **OPEN** · Filed: 2026-08-08 · Channel: CER-3
Level: **runtime-selfhost** (touches `runtime/selfhost.py`).
Source: Checkpoint Audit Loop (Constitutional Drift Audit).

## 1. Observation

`infer_write_scopes` in `runtime/selfhost.py` parses free text in intake `objective` and `accept` using regex `[a-zA-Z0-9_.-]+/[a-zA-Z0-9_./*-]+` to auto-derive top-level write scopes.

When an objective or acceptance criterion references spec sections (`spec/`), read-only reference files (`reviews/tasks/`), or test assertions inspecting core modules (e.g. `rg 'foo' kernel/types.py`), `infer_write_scopes` extracts `spec/`, `kernel/`, etc., and appends them to `plan_write_scopes`.

This grants the Builder stage full write access over protected directories (`kernel/`, `spec/`, `cli/`) that were only cited for verification or assertion, subverting SI-1 capability token isolation and the Principle of Least Privilege.

## 2. Root Cause

Regex scraping of unstructured objective and acceptance strings to infer write authorization, failing to differentiate between read/assertion targets and actual write deliverables.

## 3. Remediation Strategy

- **Short-term:** Restrict write-scope inference strictly to explicit `changed_paths` and structured deliverable declarations rather than regex-scraping free-form `objective` and `accept` strings.
- **Long-term:** Mandate structured deliverable schema in intake definitions and enforce capability token least-privilege checks.

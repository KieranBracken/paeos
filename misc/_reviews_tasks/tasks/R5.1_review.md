## What this delivers

The CER-1 review proved the runtime already depended on an abstraction (`EvidenceSource`), not a
vendor. R5.1 **generalises that into one named boundary**: `WorkerTransport`. Every way of driving a
worker and receiving its evidence — file (R5.1), the `claude` CLI (R5.2), MCP (R5.3) — satisfies it.
The **core runtime depends only on `WorkerTransport` / `EvidenceSource`, never on a vendor SDK** —
now the namespace collision is gone, adding the MCP SDK (R5.3) touches no runtime code.

## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** Strengthens AI-001/AI-003 (transport independence, read-only evidence interface): the
`SoftLoop` consumes a transport through the minimal read-only `EvidenceSource` facet; the driver uses
the full `WorkerTransport`. No new authority; submissions are inert until adjudicated (SI-2).

### 2. Architectural Drift
**PASS.** The rename is mechanical (empty `__init__`, one importer). `WorkerTransport` is a plain
Protocol; `FileWorkerTransport` wraps the existing `FileCourtEvidencePool`. Transports live under
`runtime/transports/`; the core loop (`runtime/orchestrator`) does not import them.

### 3–7. Duplication / Simplicity / Derivation / Debt
**PASS.** No duplication — `FileWorkerTransport` is a thin face over the pool; `receive` and
`evidence_for` are the same operation, so one method backs both protocols. The three verbs are the
founder's, not invented.

### 8. Security Implications
**PASS.** Vendor isolation is a security property: a compromised or churning vendor SDK sits behind
`WorkerTransport` and cannot reach the core runtime. File submissions are durable + auditable.

### 9–10. Runtime / Extensibility
**PASS.** R5.2 (`ClaudeCliWorkerTransport`) and R5.3 (`McpWorkerTransport`) now slot in behind
`WorkerTransport` with **zero core-runtime change** — the sequencing the founder asked for.

## Adversary / property pass

1. **Three verbs** — `submit`/`status`/`receive` round-trip on `FileWorkerTransport` (tested).
2. **Both protocols** — a `FileWorkerTransport` `isinstance` `WorkerTransport` and is assignable to
   `EvidenceSource` (tested; pyright-checked).
3. **Autonomous seal** — the `SoftLoop` seals on evidence submitted through the transport, consumed
   via the read-only facet (tested).
4. **Vendor independence** — `runtime/` (excluding `transports/`) imports no vendor MCP SDK (grep).

## OBSERVATION

1. **`WorkerTransport` is currently evidence-typed.** `submit`/`receive` carry `Evidence` — the R5.1
   need. R5.2's `ClaudeCliWorkerTransport` will also *dispatch work* (the execution side today behind
   `AgentRuntime`); folding execution + evidence under one `WorkerTransport` (or a sibling protocol)
   is the R5.2 design question. The boundary and the read-only facet are settled; the work-dispatch
   verbs land with R5.2.

## What this delivers — and the F2 boundary it respects

IP-0006 §5 requires every artifact to **declare** its `lifetime_class`. B2.H implements that
**kernel-safely**. The naïve reading — stamp a `lifetime_class` field onto every dataclass — would
mutate **kernel** L5/L4 types (`Evidence`, `Event`, `SealRecord`, constitution), an **F2 HARD-LOOP**
change that must route through the amendment path (B2.E), not a unilateral edit. Instead, following
the founder's own precedent (`ExecutionContext` declares L1 by *type identity*, not a field), B2.H
provides a **single runtime-side declaration**: a registry that classifies each artifact *type* to
its class. This satisfies "declare" for the whole ontology while touching **zero kernel code**.

## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** The registry transcribes IP-0006 §2/§4 verbatim (owners, persistence, the type mapping).
`may_promote` encodes §5's promotion rule — deny-by-default, with the single sanctioned exception
(L1→L3 at Stage 17) the founder named. The Evolution Layer now checks it at the one promotion site,
so the constitutional rule is enforced, not just documented.

### 2. Architectural Drift
**PASS.** A pure declaration module + one guard call. No new authority, no mutation of existing
types. `classify_type` is a lookup; `may_promote` is a table check.

### 3–7. Duplication / Bypass / Simplicity / Derivation / Debt
**PASS.** Terminology and mappings are **not invented** — they are IP-0006's own (L0–L5, the §4
falsification mapping, the L1→L3-via-Stage-17 rule). The registry is the *single* source for
lifetime classification (no per-dataclass duplication). No hidden debt.

### 8. Security Implications
**PASS.** `may_promote` is deny-by-default: any unlisted promotion, or one attempted at the wrong
stage, is refused — the machine-checkable form of the T3 defense that run-local L1 state cannot
become an L3 standing guard except through the Evolution Layer at Stage 17. `classify_type` **raises**
on an unregistered type rather than defaulting, so a new artifact kind cannot silently escape the
ontology.

### 9–10. Runtime / Extensibility
**PASS.** New artifact types register with one line; new sanctioned promotions add one table entry
keyed to their verified stage. The registry is the queryable substrate future GC / retention /
authority checks (IP-0006 §1) will consult.

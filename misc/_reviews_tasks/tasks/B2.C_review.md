## What this delivers

B2.B built the `SelfHostRunner`; B2.C makes it **launchable**. `runtime/selfhost.py` reads a JSON
backlog (`json.loads`), parses it into `Intake`s, and composes one shared `SoftLoop` over a
**durable** SQLite ledger (DEBT-0003) and the **live** `ClaudeCodeRuntime` (B2.A). `cli/paeos.py
self-host <backlog>` is the operator's one command; it exits `0` iff every intake **SEALED**, `2`
otherwise. This is the artifact the founder/ops runs to close §12 R3 → R4.

## Evaluation Checklist

### 1. Constitutional Compliance
**PASS.** The CLI *composes*; it enforces nothing. Every seal/remand is still the court's; the
driver mints no authority and holds no opinion. The signing key is loaded from the gitignored,
F3-enforced keystore (7.5 A-5) and never passed to an agent. Malformed backlog input raises
`ValueError` **before** any live call — fail fast, no side effects.

### 2. Architectural Drift
**PASS.** `parse_backlog`/`run_backlog`/`outcome_summary` are thin over the existing `SelfHostRunner`
and `SoftLoop`. No new mechanism, no new authority path. The live vs. scripted difference is a single
injected `AgentRuntime` — the seam B2.A already defined.

### 3–7. Duplication / Bypass / Simplicity / Derivation / Debt
**PASS.** Reuses the whole soft loop unchanged. Parsing is coercion-only (`object` → typed record
via small `_as_*` helpers) to keep pyright honest about JSON's `object` shape — no `cast`, no
`# type: ignore`. Lazy imports in `_self_host` keep the live-only deps (SQLite, filesystem CAS,
`ClaudeCodeRuntime`) off the import path of the pure-in-memory CLI paths. No hidden debt.

### 8. Security Implications
**PASS.** `changed_paths` feeds the kernel classifier: a backlog item touching `kernel/`/
`constitution/` classifies **KERNEL_TOUCHING** → HARD-LOOP (the runbook forbids self-hosting kernel
edits). `plan_write_scopes` bounds agent writes (barrier `ScopeViolation`). The ledger is append-only
single-writer; nothing reaches `main` without founder ratification. A forged run remands, never seals.

### 9–10. Runtime / Extensibility
**PASS.** `run_backlog` takes an injected `AgentRuntime`, `Ledger`, `CAS`, `SigningKey`, and optional
`budget_by_class`, so tests inject a scripted runtime and the CLI injects the live one through the
same door. A real backlog *source* (a queue, `spec/` items) drops in behind the JSON list.

## Adversary / property pass

1. **Parse is total and safe** — a non-list backlog raises `ValueError` (tested); a good backlog
   builds the expected `Intake` with evidence intact (tested).
2. **A good intake seals through the driver** — `run_backlog` over a scripted runtime yields exactly
   `[SEALED]` with a non-null `seal_hash` in the summary (tested).
3. **No authority invented** — the driver only wires kernel-owned components; the seal is the court's.

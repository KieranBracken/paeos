## Founder decision addendum — runtime-owned unpromoted candidate materialization

The Founder decision supplied on 2026-09-08 resolves the DEBT-0100 bootstrap deadlock within P1.
It authorizes a bounded runtime mechanism that captures the exact L12 Builder workspace output into
an immutable, unpromoted candidate for L13. This is an internal L12→L13 operation, not a new
lifecycle layer and not candidate promotion. The canonical L01–L19 spine and all authority gates
remain unchanged.

The revised P1 implementation contract is:

1. **L11 freeze before writes.** The production composition root must load the Founder-derived
   authoritative manifest and freeze a canonical plan record containing candidate/task identity,
   allowed and forbidden paths, the complete obligation set, acceptance and verifier commands,
   rollback, derivation references, test strategy, and required audit profile. The record is
   content-addressed and carried by run ID through the remaining lifecycle. Missing or mutable
   freeze inputs remand before L12.
2. **L12 Builder workspace.** The Builder receives the frozen plan and writes only inside its
   isolated governed workspace. Builder prose, stdout/stderr, exit status, MCP calls, and claimed
   evidence are non-authoritative; a Builder that omits MCP evidence must not create an evidence
   vacuum or a promotion path.
3. **Trusted materialization between L12 and L13.** After a successful L12 result, the runtime
   mechanically validates the isolated workspace, computes the exact changed-file manifest and
   deterministic tree/diff hash, stores the candidate tree and metadata in state-owned CAS, and
   emits a create-only `UNPROMOTED_PENDING_VERIFICATION` candidate record. It must bind candidate
   ID, run ID, L11 hash, actual Builder identity, base revision, workspace/environment identity,
   artifact/CAS hash, changed paths, and timestamp. It performs no semantic approval and mutates
   no authoritative source or canonical database.
4. **L13 verifier-owned observations.** The runtime derives verifier invocations from the frozen
   L11 obligation set and executes exact depth-one shell-free argv in the materialized candidate
   workspace. The kernel capture must record argv, interpreter/executable identity, cwd,
   environment fingerprint, stdout, stderr, exit code, duration, timeout, and artifact/evidence
   hashes. Only these records may enter Court. Candidate mutation, wrong workspace/run, missing
   freeze, malformed observation, empty/pending attestation, or stale binding fails closed.
5. **L13→L14→L15→L16 gating.** Court must reproduce the candidate-bound physical observations;
   deliberate failure must produce a real REMAND. L13 must independently compare all observed
   capability IDs against the frozen expected set. L14 must use a genuine external non-GPT Router
   capture with kernel Ed25519 attestation and complete authoritative scope. L15 records the
   candidate-bound evidence/ledger bundle. Only L16 may promote; L14 remand, missing L15, invalid
   receipt/report, same-family or locally fabricated provenance blocks promotion.

Required discriminators are explicit: no-MCP Builder still reaches trusted L13 capture; Builder
PASS text has no authority; fabricated observations are ignored; post-materialization mutation is
detected; missing L11 fails; failed L13 Court is REMAND; L14 remand blocks L16; direct promotion,
wrong run, and wrong workspace are rejected; and a fresh positive path produces physical Court
evidence. The implementation must include regression coverage for each discriminator and preserve
all earlier DEBT-0093–0100 records without reclassifying their remands as seals.

This addendum is the current P1 plan for independent pre-build review. It does not qualify P1 and
